# MATCH.EVENT.LOG.1.2

Виконано 2026-10-04. Версія **1.4.8**, Android **versionCode 8 / versionName 1.4.8** збережені. Автоматизовані перевірки PASS; ручне підтвердження плавності на Android ще потрібне.

Аудит та exact root cause:

MATCH.EVENT.LOG.1.1 уже використовував virtualization: при 100, 200 та 402 events існували лише **21 row Text**, один Graphics і один GeometryMask. Уся історія не rebuild-илася і не створювала сотні live objects. Unchanged per-frame refresh уже повертався без зміни рядків. Проблема полягала в тому, що shared GeometryMask був прикріплений **окремо до кожного Text**. Phaser ContainerWebGLRenderer викликає mask.preRenderWebGL/postRenderWebGL для кожного masked child; GeometryMask flush-ить batch, налаштовує stencil, малює геометрію mask, знову flush-ить і вимикає stencil. Тому один mask object не означав один mask rendering pass.

Headless-профілювання попереднього коду підтвердило **20 mask applications за кожний кадр** при 20/100/200/402 entries. Це розбивало batching і повторювало stencil/flush роботу при відкритій панелі. Додатково setScroll обходив усі 21 рядок на кожний pointermove, навіть усередині того самого visible index; при переході індексу всі тексти переприв'язувалися. При додаванні події до **закритого** log також виконувалися **21 setText call**. Однаковий текст Phaser не перерисовує, але форматування, виклики методів та перерахунок позицій усе одно були зайвими. Нові Graphics/Mask/Text при звичайному scroll або append не створювалися і раніше.

Виправлення rendering:

- Пул містить **25 Text**: visible capacity **ceil(500 / 24) = 21**, overscan **2 зверху + 2 знизу**.
- Один GeometryMask застосовується до **rowsContainer**, а не до індивідуальних Text. Виміряно **1 mask application/кадр** при відкритій панелі та **0** при закритій (зменшення 20 → 1, 95%).
- Ring reuse: на переході одного індексу оновлюється тільки рядок, який увійшов у вікно. При scroll 100 → 101 px **0 row refresh / 0 setText**, змінюється тільки container.y. При 101 → 120 px **1 refresh / 1 setText**. Тексти форматуються lazy та кешуються; cache очищається при reset.
- Row mappings зберігаються через `eventIndex`; local positions змінюються лише при переході між вікнами. Pixel offset задається одним контейнером, забезпечуючи плавний sub-row drag.
- При append оновлюються лише history metadata/maxScroll та актуальний pool. Destroy/recreate або rebuild усієї історії немає.
- 120 unchanged refresh calls виконали **0 row refresh / 0 setText**.
- Закритий log зберігає повну history та scroll metadata, але **не оновлює visual rows**. Пул hidden/inactive, scroll input disabled, mask не рендериться. У профілюванні 50 послідовних closed appends дали **0 visual refresh / 0 setText**.
- Toggle перевикористовує той самий panel, container, pool, input zone і mask. Open показує latest, як і раніше. Close очищає активний drag та вимикає input.
